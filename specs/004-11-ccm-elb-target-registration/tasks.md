# Execution Graph (DAG): CCM ELB Target Registration (Node providerID + RBAC)

**Input**: Design documents from `/specs/004-11-ccm-elb-target-registration/`
**Prerequisites**: `plan.md` (architecture), `spec.md` (requirements + AC)
**Estimate**: 4 implementation tasks + 6 verification gates

## Stage 1: Implementation

- [x] T001 [Stage 1: RBAC] In `terraform/environments/dev/manifests/aws-ccm.yaml`: in the `system:aws-cloud-controller-manager` ClusterRole `rules` (lines ~22–49), add `get` + `watch` to the `services` rule (becomes `["get","list","watch","patch","update","create","delete"]`) and to the `services/status` rule (becomes `["get","list","watch","patch","update"]`) — `kubectl auth can-i` confirmed `watch services -> no` and `get services -> no`, causing the repeating `Failed to watch *v1.Service: unknown (get services)` error in the CCM log; the upstream cloud-provider-aws RBAC grants get/list/watch on services
- [x] T002 [Stage 1: Control-Plane Bootstrap] In `terraform/modules/control-plane/bootstrap.sh`: (1) fetch the AZ via IMDSv2 (`AZ=$(curl -s -H "X-aws-ec2-metadata-token: ${IMDS_TOKEN}" http://169.254.169.254/latest/meta-data/placement/availability-zone)`) alongside the existing `PRIVATE_IP`/`INSTANCE_ID` fetches and extend the fail-fast guard to include `AZ`; (2) add `kubeletExtraArgs.provider-id: aws://${AZ}/${INSTANCE_ID}` to `nodeRegistration` in `kubeadm-config.yaml` and configure `/etc/sysconfig/kubelet` with `KUBELET_EXTRA_ARGS="--provider-id=aws://${AZ}/${INSTANCE_ID}"` — the CCM's default `--aws-node-name=NodeNameProviderID` requires `spec.providerID` to map nodes to EC2 instances; without it the CCM logs `node has no providerID` and never registers ELB targets
- [x] T003 [Stage 1: Worker Bootstrap] In `terraform/modules/worker-nodes/bootstrap.sh`: (1) add an IMDSv2 fetch block after the `K8S_VERSION`/`SSM_PARAM_NAME` block (~line 12) — token + `INSTANCE_ID` + `AZ` with a fail-fast guard, mirroring the control-plane pattern; (2) configure `/etc/sysconfig/kubelet` with `KUBELET_EXTRA_ARGS="--provider-id=aws://${AZ}/${INSTANCE_ID}"` before joining (kubeadm join does not take a `--provider-id` CLI flag) — sets each worker node's `spec.providerID` at `kubelet` registration time (Depends on T002 for the shared IMDS pattern)
- [x] T004 [Stage 1: In-Place Repair] In `terraform/environments/dev/main.tf`: add a new `null_resource.set_node_provider_ids` with an SSM Run Command on the control plane that, for each node, maps its InternalIP → instance ID + AZ via `aws ec2 describe-instances --filters "Name=private-ip-address,Values=${ip}"` and runs `kubectl patch node <name> --type merge -p '{"spec":{"providerID":"aws://<az>/<id>"}}'` (idempotent — re-patching the same value is a no-op); triggers = `instance_id = module.control_plane.control_plane_instance_id` + `provider_id_ref = "1"`; chain it before the CCM by adding `null_resource.set_node_provider_ids` to `apply_aws_ccm`'s `depends_on` — the current cluster's nodes already booted without providerIDs (bootstrap fixes only apply to future recreations), so this one-time repair heals them in place without a `terraform destroy` (Depends on T002, T003)
